# How the code is put together

What each folder holds, and the conventions every change follows. CLAUDE.md lists the folders in a line each and points here.


| Path | What |
| --- | --- |
| `apps/server` | The server: one Node process. `server.ts` boots `@highsea-tv/runtime`, then serves `/api` with Hono and everything else with Next (ADR 0003), on webpack with react-native-web since D1. `src/admin/` holds only what needs the server: the session and the providers, with the style registry from `@highsea-tv/ui/next/style-registry`; the screens are `@highsea-tv/admin`'s |
| `packages/admin` | The admin's screens, `@highsea-tv/admin` (one-client-platform-d.md): written once, drawn by `apps/server`'s routes over `/api/v1` and by the prototype over `@highsea-tv/mock`'s transport (ADR 0018's 2026-11-04 section). `navigation.tsx` is the host's seam for the router; since D1 `shell.tsx` and `system.tsx`'s Status draw with the library's native renderer, and since D2 the library and the work (the dashboard to Curation), and since D3 everything else: every Settings area, System's tabs, the flows and Shows' drafted admin (drawn only when shows are served, `serves.tsx`) |
| `apps/desktop` | The desktop app (ADR 0058): Tauri 2 around `apps/client`'s desktop export (`export:desktop`, `dist-desktop/`, with `EXPO_PUBLIC_HIGHSEA_APP=desktop`). `src-tauri/src/` is the Rust side: `proxy.rs` (the API, the event stream and the `server` scheme, each with the device token), `keychain.rs`, `servers.rs` (`servers.json`), `discovery.rs`, `oidc.rs`. The page's side is `apps/client/src/desktop/tauri.tsx`, loaded only in the desktop export (`app.ts`). Its own CI is `.github/workflows/desktop.yml`; the updater's development key and the owner's steps for the release key are in `keys/` |
| `apps/client` | The one client (ADR 0061), `@highsea-tv/app`: one Expo project (SDK 58 on react-native-tvos) for the phone, the TV and the web, with one route tree under `src/app/` and one shell picked by the form-factor rule (`useFormFactor`). The web is `expo export -p web` with `experiments.baseUrl: '/web'`, which `apps/server/src/web/` serves at `/web` since C1 (routes fall back to `index.html`, hashed scripts and assets cached for good, under a CSP), the image building it and copying only `dist/`; `bun run web` is its dev server, proxying `/api` and `/stream` (`dev-proxy.js`); `EXPO_TV=1` at prebuild makes the TV's project. `export:desktop` makes the desktop app's export into `dist-desktop/`, its base at the window's root and the Tauri code in only behind `EXPO_PUBLIC_HIGHSEA_APP=desktop`. It ships as `tv.highsea.mobile` and `tv.highsea.tv`, with the scheme `highsea`. Platform files are pairs (`host.ts`/`host.web.ts`), held by `test/platform-files.test.ts`. Since B2 it has every films screen (the gate, the shell, Home, Library, a film, a person, Search, Alerts, Settings, the player, Connect a device, Profile, Offline and Downloads, and the desktop app's chrome behind `src/desktop/host.ts`'s seam); shows and music come in B3. What the phone and the TV share beyond drawing is `@highsea-tv/native` (the servers it knows with tokens in the keychain, discovery, the session and the player on expo-video). Its mock export (`dist-mock`) is the client prototype inside `design/prototypes`' frames; `uitest/` is the layout check's XCUITest, `dpad-walk/` the TV's remote walk and `.maestro/` the phone's flow. CI is `.github/workflows/native.yml`. It replaced `apps/mobile` and `apps/tv`, removed in B2 |
| `apps/packages` | highsea's Synology package source at `packages.highsea.tv` (ADR 0050's 2026-10-29 section): one Vercel Function (`api/index.ts`) answering Package Center as SynoCommunity's spkrepo does, from the `highsea-spk.json` on GitHub's Latest release, with the icons in `public/` |
| `apps/docs` | The public guides at `docs.highsea.tv`: Fumadocs on Next, exported as static files, in the design system's tokens. Guides are MDX in `content/`, with `install/` and `settings/` as folders (sidebar order in each `meta.json`; redirects for moved pages in `vercel.json`). A change to what the admin does updates its guide, and retakes its screenshots (`public/images/admin/<area>/`, listed in `scripts/docs-shots/areas/`), in the same change; `test/content.test.ts` checks their links, frontmatter and copy. Vercel's `highsea-docs` project (root `apps/docs`) deploys every push to `main`; pull requests get previews behind Vercel's sign-in |
| `design/prototypes` | The signed-off prototypes, with an SDK-shaped mock server (`src/mock/`): the reference for every screen and the first draft of the API |
| `packages/core`, `db`, `jobs`, `runtime`, `i18n` | The platform. Since 8b the runtime also holds the owner's tools (ADR 0047): backups and restore (`backups.ts`, with its own zip writer and reader in `zip.ts`; a restore exits with code 75 for Docker to restart it), the log files (`logs.ts`), crash reports, `/metrics` and Updates (`operations.ts`), and turns the domains' events into notifications (`notify.ts`) |
| `packages/auth`, `network` | People and access (ADR 0023–0025); discovery, proxies and TLS (ADR 0020, 0026) |
| `packages/personalization` | Preferences in layers (ADR 0027), the widget registry and dashboard layouts, the home layout, themes, branding and sound packs (ADR 0028) |
| `packages/parser` | Release names into their parts: title, year, edition, quality, languages, group. Pure |
| `packages/quality` | The quality vocabulary, profiles, custom formats, sizes and the decision engine (ADR 0031). Pure; browsers import `@highsea-tv/quality/browser`, which leaves out the TRaSH presets |
| `packages/metadata` | TMDB behind the fetch seam (ADR 0029), the metadata cache, images and refresh (ADR 0030); the replaying `fetch` in `@highsea-tv/metadata/replay` |
| `packages/schemas`, `catalog`, `indexers` | Shared data formats, one subpath each: `@highsea-tv/schemas/indexers`, the indexer definition format (ADR 0033, 0036); the signed catalog, its pipeline and seed (ADR 0034); the indexer engine, health and release search, with a fake indexer in `@highsea-tv/indexers/fake` (ADR 0035) |
| `packages/media` | The media libraries, one subpath per type (ADR 0036). `@highsea-tv/media/shared`, what every type shares: root folders, the seeded profiles, formats and sizes (`createMedia`, created once by the runtime), names, paging and the API's common shapes. `@highsea-tv/media/movies`, the movie library: items and versions (ADR 0012), availability, the parser's page, the client API's reads, the import pipeline (ADR 0039), and 6b's archive extraction (`unar`), the library scan with filesystem watching, and the existing-library import. `@highsea-tv/media/naming`, the naming function the import and the Settings preview share; `@highsea-tv/media/testing`, short ffmpeg clips for tests (ADR 0040) |
| `packages/stream` | Playback (ADR 0051, 0052), one subpath each: `profiles` (the device profile's shape, the browsers' built-in profiles and reports laid over them), `decision` (direct play, direct stream or transcode, with reasons; pure), `sessions` (live play sessions in memory and their HMAC stream tokens), `hls` (playlists, ffmpeg's command lines, and the runs that make segments on demand into the data folder's `transcodes/`), `trickplay` (the scrubber's sheets). The runtime's `playback.ts` joins it to the library, and `trickplay.ts` runs the `media.trickplay` job; `apps/server/src/stream/` serves `/stream` (files, HLS, WebVTT and the test page with hls.js). Watch state is `@highsea-tv/media/shared`'s `createWatch` (ADR 0054) |
| `packages/torrent` | The in-process BitTorrent engine (ADR 0005, 0037): sessions, peers, the picker, storage, fast resume, SHA-1 in the worker pool, bound to the address the VPN allows; uTP, IPv6, protocol encryption (MSE), the IP blocklist and UPnP/NAT-PMP (6b); a tracker and torrent makers in `@highsea-tv/torrent/testing` |
| `packages/downloads` | Grabs, the queue and its monitor, stalls and replacements, the blocklist, seeding rules and history (ADR 0038), categories, the watch folder and the IP blocklist's updates (6b); finished downloads go to the movie import pipeline (ADR 0039) |
| `packages/vpn` | Settings › VPN (docs/product/vpn.md, ADR 0042): highsea connects (its own WireGuard tunnel, Linux only, with the providers from the catalog and their port forwarding), the VPN container (gluetun’s control server) and interface modes, the checks, and the binding handed to the engine; a fake gluetun in `@highsea-tv/vpn/fake` |
| `packages/subtitles` | Subtitles (ADR 0043), one subpath each: `shared` (languages, profiles, Bazarr's scoring, throttling, sidecar names, the moviehash, processing), `providers` (OpenSubtitles.com, Subdl, SubSource and the zip reader), `movies` (the service: accounts, the wanted list, search, downloads, the import's hooks, the jobs, the sync and the offset), `sync` (the engine, ADR 0044: the reference, ffmpeg and the WebAssembly VAD, alignment and confidence, run as a worker-pool task), fakes of the three providers in `@highsea-tv/subtitles/fake`, and the Sintel fixture and clip makers in `@highsea-tv/subtitles/testing`. The runtime hands media the import hooks and the client's track reader, so media never imports it |
| `packages/lists` | Import lists (ADR 0045), one subpath each: `tmdb` (lists and charts through `@highsea-tv/metadata`), `trakt` (charts, public lists, and the account's watchlist after the device flow; tokens sealed), `generic` (StevenLu and MDBList JSON), `service` (the lists, their 6-hourly sync, exclusions), `shared`; fakes of Trakt and generic lists in `@highsea-tv/lists/fake`. The runtime hands it the library (`ListLibrary`), so lists never import media. Automation itself (RSS, the sweep, `movies.search`) is the runtime's `automation.ts` |
| `packages/notifications` | Notifications (ADR 0046), one subpath each: `service` (connections, the event catalogue, messages in i18n, the `notifications.send` job with retries and `Retry-After`, the log, web push subscriptions and the server's mail), `channels` (Discord, Slack, Telegram, ntfy, Gotify, Pushover, Matrix, Email through Nodemailer, Webhook, Apprise and Browser through `web-push`), `shared`, and `mail`, the email templates (docs/product/emails.md): MJML and plain text, browser-safe, which the prototypes' preview imports too; the server compiles them with `mjml` (`src/mail/compile.ts`, never imported by the browser) and attaches the logo and poster by Content-ID. In `@highsea-tv/notifications/fake`, a recording fetch for every service, a browser's side of web push, and an SMTP server on loopback. The runtime raises the events from hooks the domain packages expose, so they never import it |
| `packages/curation` | Curation (ADR 0048), in `@highsea-tv/curation/service`: announcements (placements, audience, schedule, who has seen and acknowledged them) and featured sections (hand-picked or by rule, with per-movie artwork and taglines), resolved per person and kind of app, the `curation.schedule` job and the preview. Smart collections (ADR 0049) in `@highsea-tv/curation/collections`: rules, picks and exceptions, checked, put in words and evaluated when read; the runtime compiles the rules to SQL (`collection-query.ts`) over the facts in migration 0012 and hands it a `CollectionLibrary`. The runtime hands it the library (`CurationLibrary`), so curation never imports media |
| `packages/importers` | One-time migration (ADR 0041), one subpath each: `@highsea-tv/importers/radarr` (API v3) and `@highsea-tv/importers/qbittorrent` (WebUI API v2, 4.5.0 or later); fakes of both in `@highsea-tv/importers/fake`. Settings › Migration, owner only |
| `packages/client` | What the clients share besides drawing (ADR 0055), one subpath each: `data` (the hooks over `@highsea-tv/sdk/react`), `format` (times, meta lines, captions), `prefs` (a device's theme and sound from ADR 0027's layers); 4.2b adds `player`, and 4.5a `library` (the shelves) and `servers` (the servers an app knows). React without the DOM, so React Native can import it; the prototype imports its `format` |
| `packages/ui` | The design system's one component library (ADR 0060), `@highsea-tv/ui`: each component drawn once, in React Native (`src/native`, the TV's rule in `src/native/tv`), on the web through react-native-web; the web renderer went in D3. Where the web needs other code, a pair of platform files (`name.web.tsx` beside `name.tsx`), listed with its reason in `src/shared/parity.ts`. `src/next/` is the Next.js hosts' wiring (`libraryWebpack` in `./next/webpack`, `StyleRegistry` in `./next/style-registry`), which the server and the guides share. Every control takes its size, corner and colours from the control spec in the tokens (docs/design-language/controls.md) |
| `packages/mock` | The prototypes' mock server as an SDK transport (ADR 0061), `@highsea-tv/mock`: `/transport` answers the SDK's routes from seeded state (501 for the rest), and `/frame` is the postMessage channel between the prototypes' frames and the client. Only mock builds load it (`bundles.ts`) |
| `packages/api-contract`, `sdk` | The public API's zod/OpenAPI contract, and the typed client every app uses |
| `packages/tokens`, `brand`, `fixtures` | The design system: the tokens (the control spec in `src/controls.ts`, the `--control-*` CSS per platform), the brand and the fixtures |
| `docs/` | Roadmap, plans, ADRs, product specs, brand and design language |
| `templates/` | The NAS templates (Unraid's XML, compose files for TrueNAS and Synology, and the Synology package in `synology/spk/`, which `scripts/spk.ts` builds) and the store listings for TrueNAS's community train, Umbrel and CasaOS, copied into those stores' repositories by pull request (`templates/README.md`). `ca_profile.xml` at the root is Unraid's Community Applications profile |
| `scripts/` | License audit, dependency check, version pinning, browser sweeps; `image.ts` (the slim image's production install, its size and attestation checks), `e2e/` (the end-to-end run through the container and its fixtures service) and `release.ts` (versions, image tags, the changelog's notes and preparing a release, ADR 0050) |

Conventions:

- **Packages export raw TypeScript** (`"exports": { ".": "./src/index.ts" }`) and import with `.ts` extensions. Domain packages with several kinds export one subpath each and no root (`@highsea-tv/schemas/indexers`, `@highsea-tv/media/movies`; ADR 0036): a new kind is a folder under `src/` and `test/` and a line in `exports`. Node runs it with type stripping, so only erasable syntax compiles (`erasableSyntaxOnly`): no enums, no namespaces with values, no parameter properties.
- **The admin reads and writes through the public API,** never Server Actions (ADR 0018).
  - It uses `@highsea-tv/sdk/react`: `useQuery(key, call, topics)` and `useAction(call)`.
  - Screens live in `@highsea-tv/admin` (`packages/admin`), shared with the prototype, which draws them over the mock transport (`design/prototypes/src/admin/shared.tsx`); the prototype's own copies are ported there by swapping the mock client for the SDK, batch by batch.
- **API routes** are declared in `@highsea-tv/api-contract` and implemented in `apps/server/src/api/`. After changing the contract, run `bun run openapi` in `apps/server`; a test fails when `openapi.json` is stale.
- **Database:**
  - change `packages/db/src/schema/`, then run `bun run generate` in `packages/db` (drizzle-kit, then the embed);
  - a test fails when the embedded migrations are stale;
  - tests use `bun:sqlite`, production `better-sqlite3` (ADR 0019).
- **Jobs** run at least once, so every handler must be safe to repeat (ADR 0022).
- **Strings** go in `@highsea-tv/i18n` catalogs (`defineMessages`), not inline (ADR 0021).
- **`@highsea-tv/ui`** is React Native everywhere: a Next.js host takes `libraryWebpack` and `StyleRegistry` from `@highsea-tv/ui/next/*` and builds with `--webpack`. Screens draw controls only with the library: `bun scripts/controls.ts` finds any drawn by hand, with exceptions and their reasons in `scripts/control-exceptions.json`, and `bun scripts/bundles.ts` checks that each app's bundle carries only its own renderer.


## Commands

Every command, with the development switches, the image, release and packaging. CLAUDE.md keeps the everyday ones.

```sh
bun install
bun run lint            # Biome
bun run typecheck       # every workspace, plus scripts/
bun run test            # everything (Bun's runner, each file isolated)
bun run smoke           # the platform under Node, as production runs it
bun run check:node      # is `node` the version in .nvmrc (26.11.1)?

bun run server          # the server in development, http://localhost:3000 (data in .dev/)
HIGHSEA_TMDB_REPLAY=1 bun run server   # the same, answering TMDB from the recordings: no key, no network
HIGHSEA_TORRENT_OFFLINE=1 bun run server   # the torrent engine opens no sockets: grabs queue, nothing downloads
HIGHSEA_SUBTITLES_FAKE=1 bun run server    # the subtitle providers are fakes: no accounts, no network
HIGHSEA_LISTS_FAKE=1 bun run server        # Trakt and generic lists are fakes; Trakt's device code is approved at once
HIGHSEA_PLAYBACK_TRY=1 bun run server      # also serves /stream/try, the playback test page (never in the image's defaults)
HIGHSEA_HARDWARE_NONE=1 bun run server     # no graphics chip is looked for (the sweeps and the guides' screenshots set it)
bun run --cwd apps/desktop dev   # the desktop app around the client's desktop export (Rust from rust-toolchain.toml); checks add --config '{"identifier":"tv.highsea.desktop.test"}'
bun run web             # the client's Expo dev server for the web, http://localhost:3200/ (the base URL is production-only), proxying /api and /stream to bun run server
bun run prototypes      # the Phase 2 prototypes, http://localhost:4500
bun run one-place       # fails when a component, screen or value is defined in two places (exceptions in scripts/one-place-exceptions.json)
bun run --cwd apps/client export:web:mock   # the client's web export on the mock (dist-mock), which the prototypes' frames hold
bun run --cwd apps/client export:web        # the client's web export for /web (dist/)
bun run --cwd apps/client prebuild          # the client's iPhone project (prebuild:tv for the Apple TV's, EXPO_TV=1); ios/ is never committed
bun run --cwd apps/client ios               # build and run it on the simulator with Metro (`tv` for the Apple TV's)
bun run --cwd apps/client test              # its Jest tests (bun run test runs them too)

bun run pin hono zod    # versions old enough to pin
bun run licenses        # the license audit
bun run catalog:build   # validate, bundle and sign the catalog (dev key unless HIGHSEA_CATALOG_KEY)
bun run record:tmdb     # in packages/metadata: refresh the TMDB recordings, with HIGHSEA_TMDB_READ_TOKEN from .env.local (never in CI)
bun scripts/calibrate-sync.ts <library> --cache <dir>   # the sync's confidence on real films: reads them, never writes (never in CI)
docker compose -f compose.dev.yaml up --build   # the image from this checkout (compose.yaml runs the published one)
bun run audit           # the dependency check: npm's advisories, exceptions in scripts/audit-exceptions.json
actionlint              # the workflows in .github/workflows, before a push that changes them (brew install actionlint)
HIGHSEA_IMAGE=highsea:dev bun scripts/e2e/run.ts   # the end-to-end run through the image (compose.e2e.yaml)
bun scripts/image.ts size highsea:dev               # the image's size and largest folders (no budget since 2026-11-05)
bun scripts/image.ts hardware highsea:dev           # its hardware encoders, filters and drivers (ADR 0056)
bun scripts/image.ts user highsea:dev               # the user its entrypoint picks from /data (ADR 0057)
bun scripts/spk.ts build 0.2.0 [--build 2]         # the Synology package, dist/highsea-0.2.0-0001.spk (templates/synology/spk)
bun run docs            # the guides (apps/docs), http://localhost:3100
sh apps/docs/public/install.sh --print-compose   # the compose file get.highsea.tv's installer writes
(cd apps/docs/public && shasum -a 256 install.sh > install.sh.sha256)   # after changing the installer (a test checks it)
bun scripts/docs-shots/run.ts [area ...]   # the guides' screenshots of the admin, from the sweep's seeded server
bun scripts/release.ts prepare 0.1.0   # a release's commit: changelog, version, releases.json, catalog version, seed, openapi.json
bun scripts/release.ts check 0.1.0     # what the release workflow checks first (also notes, tags, trust)
```

Browser sweeps are in [scripts/sweeps](../scripts/sweeps/README.md) (the server they boot and seed is `scripts/sweeps/seeded.ts`, which the guides' screenshots share): axe in three themes, overflow, 200% text, reduced motion, and the keyboard and D-pad walks. They cover the prototypes (from a build they serve themselves, so `bun run prototypes` isn't needed; `pages.ts` and `keyboard.ts` take a platform, for sweeping only what a fix touched) and, with `bun scripts/sweeps/server.ts`, the server's real admin pages from the production build (`SWEEP_DEV=1` for the dev server). Run them before each checkpoint report. `bun scripts/sweeps/compare.ts` puts every admin screen beside its prototype for the owner's review. `bun scripts/sweeps/playback.ts` plays films in the web player in Chromium and Firefox (`bunx playwright-core install chromium firefox` once). `bun scripts/sweeps/phone.ts` signs in and plays Sintel in the client's iPhone build on a booted simulator through Maestro (`~/.maestro/bin` on the PATH; a Release simulator build signed ad hoc, as its header says). `bun scripts/sweeps/tv.ts` walks the client's Apple TV build with the remote on a booted Apple TV simulator (an XCUITest, `apps/client/dpad-walk`, through XcodeGen; the app installed and signed in). `bun scripts/sweeps/layout.ts` compares the one client's screens between the web and the iPhone and Apple TV simulators from their accessibility trees, failing on drift beyond 4 pt (`build both` first makes the mock-mode builds; `--preflight` takes one screen); its sheet goes outside the repo. `bun run one-place` fails when anything is defined in two places.
