# Settings

- **Platforms:** Admin, every breakpoint.
- **Prototype:** `#/admin/settings` (the index) and `#/admin/settings/{area}` (A15, reference fidelity; Appearance and Users and devices are core, in [appearance.md](appearance.md) and [users-devices.md](users-devices.md)).
- **Roadmap:** [Phase 2 › A15](../roadmap.md#phase-2-design-prototypes-gate-user-sign-off), [Admin UI routes](../roadmap.md#admin-ui-routes-built-to-match-the-phase-2-prototypes) (`/settings/*`).

## Purpose

Everything about how the server runs, in one place, one area per page: the region and updates, how it looks, how it's reached, how people sign in, backups, people, the library's naming and quality, the download client, and notifications.

## Entry points

- Sidebar › **Settings** (owners and admins); the palette (every area by name).
- **Security** and **Backups** are the owner's alone ([ADR 0032](../adr/0032-administrative-and-normal-access.md)): admins don't see them in the index or beside an area, and their addresses say there's no setting there. So are **VPN** and **Download client** (checkpoint 6, judgement call 13), like the other network settings. **Migration** (6b) is the owner's too: the importers take another program's credentials.
- Links from elsewhere: Backups from System › Backups, Download client from Downloads. Setup's first step mentions Migration ("Coming from Radarr or qBittorrent? You can bring your library across after setup."), as plain text, because the admin opens only once setup has signed the owner in.

## Layout

- **The index** (`/settings`): four groups (Server, People, Library, Downloads and alerts), and since 6b a fifth, System, with Migration, each a grid of cards (1, 2 or 3 across) with the area's icon, name and one line on what's inside. Subtitles links to its own page.
- **An area** (`/settings/{area}`): the page header with the area's name and line; from expanded, the areas beside the content (grouped, the current one marked); below expanded, **All settings** back to the index. Content is a stack of **groups** (a titled card each).
- **The save bar:** while an area has unsaved changes, "You have unsaved changes." with **Discard** and **Save** sticks to the bottom of the page.

## States

- **Loading:** "Loading…" in the area; **error:** "Couldn't load these settings." and the server's message.
- **Unsaved:** the save bar. **Saved:** "Settings saved".
- **Warnings in place:** TLS off ("Without TLS, passwords cross the network in the clear. Keep it to the LAN."); backups off ("Without backups, a failed disk takes your settings, history and users with it."); a bad external URL ("Use a full address, like https://harbor.example.net.").
- **Not found:** an unknown area: "There's no setting here" with **All settings**.
- **Reference fidelity:** controls marked "Not in the prototype" (editing a profile, adding a list or a connection, presets, the certificate, handing the server over) show a tooltip and do nothing.

## Interactions

- **Edit, then Save or Discard.** Nothing applies until Save; leaving the area keeps nothing.
- **Check from outside** asks the server to reach its own external URL from outside and reports the time and certificate.
- **Test** sends a test notification to that channel.
- **Keyboard:** native controls in reading order; the area nav is a list of links.

## Data

- `settings.get(section)` / `settings.save(section, value)` → `GET|PUT /api/v1/settings/{section}` for `general`, `mediaManagement`, `downloadClient`, `vpn` ([vpn.md](vpn.md)), `network`, `security`, `backups`, `connections`, `importLists` (draft shapes in `design/prototypes/src/mock/settings.ts`). *Import lists, as built (8a),* have their own routes instead: `importLists.list`, `add`, `update`, `remove`, `sync`, `test`, `exclusions`, `removeExclusion`, `trakt`, `traktConnect`, `traktPoll`, `traktDisconnect` at `/api/v1/import-lists` (staff); event `lists.updated`. Network and Security are built (checkpoint 2); `mediaManagement`, `downloadClient` and `vpn` with checkpoint 6a; the rest come with their checkpoints. Setup's `media` row became `folders`, so these names are settings.md's sections (the checkpoint's judgement call 3).
- **Media management** (checkpoint 6a): `settings.mediaManagement()`, `settings.saveMediaManagement(value)` → `GET|PUT /api/v1/settings/mediaManagement` (staff) → `MediaManagementSettings`: `rename`, `folderFormat`, `fileFormat`, `colonReplacement`, `hardlinks`, `nfo`, `unmonitorDeleted`, `permissions`, `chmod` (three octal digits), `recycleBin` (a path, or empty to delete straight away) and `recycleBinDays`.
- **Download client** (checkpoint 6a): `settings.downloadClient()`, `settings.saveDownloadClient(value)` → `GET|PUT /api/v1/settings/downloadClient` (the owner's) → `DownloadClientSettings`: `port` (1024–65535), `encryption` (`require`, `prefer` or `allow`), `upnp`, `utp` (6b; on by default), `maxActive` (1–20), `downloadRate` and `uploadRate` (bytes per second, 0 for none; A8's Limits edit them too), `seedRatio` and `seedMinutes` (null for no limit). The admin shows the time in hours. 6b adds `watchFolder` (an absolute path inside the data folder or the downloads folder, or null for off) and `watchCategory` (`manual` by default; one of the categories, never `movies`). The categories themselves are `downloads.categories()`, `saveCategory` and `removeCategory` at `/api/v1/torrents/categories` ([activity-downloads.md](activity-downloads.md#data)), stored in the `torrentCategories` settings row; saving and removing are the owner's. Since 6b, `blocklistUrl` too: an http(s) address or a path in the config folder, `''` for none (ADR 0037).
- **Migration** (6b, the owner's; [ADR 0041](../adr/0041-migration-importers.md)): `importers.radarrTest`, `radarrPreview`, `radarrRun` → `POST /api/v1/importers/radarr/{test,preview,run}`, and `importers.radarrStatus()` → `GET /api/v1/importers/radarr`; `importers.qbittorrentTest`, `qbittorrentPreview`, `qbittorrentRun`, `qbittorrentResume` → `POST /api/v1/importers/qbittorrent/{test,preview,run,resume}`, and `importers.qbittorrentStatus()` → `GET /api/v1/importers/qbittorrent`. The connection is `{ url, apiKey }` or `{ url, username, password }`, with `pathMappings: { from, to }[]`; Radarr's run adds `profiles` (Radarr's id → highsea's) and `settings`. Status is `{ state, total, done, imported, skipped, failures, startedAt, finishedAt }`, plus `paused`, `checking` and `resumedAt` for qBittorrent, live on `migration.updated`. Runs and resumes go in the audit log, without credentials.
- **General › Metadata** (checkpoint 4): the TMDB key, the metadata language and the region live together in one settings row, `GET`, `PUT` and `DELETE /api/v1/settings/metadata`:
  - `settings.metadata()` (staff) → `MetadataSettings`: `key` (`set`, and `last4`, its last four characters; never the key itself), `language` (`en-US`, TMDB's language parameter) and `region` (`GB`, ISO 3166-1; the owner's locale by default, set in setup);
  - `settings.saveMetadata({ body })` (the owner) → `PUT`, any of `key`, `language` and `region`. A new key is checked with TMDB first (400 `tmdb-key-rejected`; 503 `tmdb-unreachable` or 429 `tmdb-rate-limited` when TMDB can't say), and nothing is saved unless every field is. The key is stored encrypted;
  - `settings.removeMetadataKey()` (the owner) → `DELETE`. The library and its pages keep working from the cache.
- **General › Indexer catalog** (checkpoint 5): `catalog.settings()` and `catalog.updateSettings(patch)` → `GET`, `PATCH /api/v1/catalog/settings`, both the owner's. Each change saves at once; an admin sees a line saying only the owner can change them. See [indexers.md › Data](indexers.md#data).
- **Quality sizes:** `settings.qualitySizes()` → `GET /api/v1/settings/qualitySizes` (staff): `{ quality, min, preferred, max }` per quality, lowest first, in MiB per minute. Read-only until checkpoint 8.
- **Profiles and formats:** `quality.profiles()` → `GET /api/v1/qualityprofiles[/{id}]` and `quality.customFormats()` → `GET /api/v1/customformats`, both staff. Seeded and read-only until checkpoint 8 ([ADR 0031](../adr/0031-quality-and-the-decision-engine.md)).
- **Root folders** (Media management › Importing): [movies.md › Data](movies.md#data). *As built (6b):* each root folder gains a ghost link beside **Remove**, **Import what’s already here** ("Import the movies already in {path}" for screen readers), which opens [Manual import › Library import](manual-import.md#library-import-6b) on that folder.
- Events: `settings.updated`.

## Decisions

- **An index, then one area per page,** rather than one long page: each area's address can be linked from where its setting matters (Downloads → Download client, System → Backups).
- **Drafts with a save bar** for settings pages; immediate saves for lists (curation, people), where each change is its own action.
- **Subtitles stays on its own page** and is listed here as a link, so its settings and its wanted list sit together.
- **Backups split:** the schedule is a setting; making and restoring a backup is an action on System.

- **The TMDB key lives in General › Metadata,** with the metadata language and region; setup sets it first, and every missing-key message links here. Approved by the owner on 2026-10-20 ([checkpoint 4 plan](../plans/phase-3-checkpoint-4.md#owners-decisions)); the prototype doesn't show the group.
- **The catalog's settings sit in General after Metadata,** owner only, and the search timeout stays a fixed 30 seconds (checkpoint 5, answer 7). The prototype doesn't show the group.
- **Profiles and formats stay read-only until checkpoint 8.** Their editors are prototyped and approved first.
- **Settings › VPN** is its own area, before Download client, prototyped and approved by the owner on 2026-10-20 ([vpn.md](vpn.md)); Download client's VPN group became one line.
- **The default seeding rule lives in Download client** (checkpoint 6a): an indexer's rule (A9) falls back to it, and Downloads' Seeding tab only reads it, so no prototype screen set it. Times are entered in hours.
- **Migration sits in a System group of its own** (6b, the owner's answer 10), the first area there. Its connections aren't saved: they're entered for each run and ride sealed in the job.
