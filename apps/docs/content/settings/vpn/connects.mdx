Written for highsea 0.1.0.

highsea brings up a WireGuard tunnel inside its own container and binds every torrent to the tunnel's address. A packet from that address can only leave through the tunnel, so if the tunnel drops, torrents stop rather than fall back to your own connection.

![Settings › VPN with the built-in VPN chosen: the Provider list set to Proton VPN, that provider's three steps, and WireGuard configuration with Upload a file and Paste instead](/images/admin/settings-vpn/connects.png)

## What it needs

- **Linux.** highsea's Docker image runs Linux, so this works wherever highsea runs in Docker. If you run highsea some other way on macOS or Windows, use another mode.
- **The NET_ADMIN capability** for highsea's container, so it can make its own network interface and routes. This reaches only highsea's container, not the host.
- **Its own network**, not host networking. With host networking, highsea's interface and routes would land in the host's network beside everything else.
- **The TUN device**, only on older kernels without WireGuard built in (Linux before 5.6, which some NAS systems still run).

Settings › VPN writes the lines for you. Under the provider's fields, open **Compose for the built-in VPN** and choose **Copy**. The lines give highsea's service the capability, publish its ports in place of `network_mode: host`, and hold the TUN device as a comment, for a kernel that needs it. Paste them into highsea's service in your compose file, take out `network_mode: host`, then recreate the container.

![Settings › VPN with the built-in VPN chosen and Compose for the built-in VPN open: the lines for highsea's service, with cap_add NET_ADMIN, the published ports and the TUN device as a comment, and a Copy button](/images/admin/settings-vpn/connects-compose.png)

Because the container doesn't use host networking, apps on your network find the server through the UDP broadcast on port 7368 rather than mDNS. See [Discovery](/settings/network/#discovery).

The status at the top of the page says when the container isn't set up for the tunnel yet:

- **highsea is on host networking** means highsea's container still shares the host's network. highsea won't start the tunnel there, and **Reconnect** stays off. Put the lines from **Compose for the built-in VPN** in place of `network_mode: host`, then recreate the container.
- **highsea can't run the tunnel yet** means the container lacks the NET_ADMIN capability. The same lines add it.

In either case **Compose for the built-in VPN** opens by itself. When the tunnel can run, it stays folded until you open it.

## Pick your provider

Choose your provider under **Provider**. highsea shows that provider's own steps beneath it. Most providers give you a WireGuard configuration file to download; upload it with **Upload a file**, or choose **Paste instead** and paste its contents. Once saved, the file's keys stay on the server: the page shows only the file's name, with **Replace the file** to change it.

| Provider | How highsea connects | Port forwarding |
| --- | --- | --- |
| Proton VPN | A WireGuard file from Downloads › WireGuard configuration, on a server marked P2P with NAT-PMP (port forwarding) turned on | Automatic |
| Private Internet Access | Your PIA username and password, and a **Region**. highsea registers its own WireGuard key with PIA, so there's no file. | Automatic |
| AirVPN | A WireGuard file from Client Area › Config Generator (Linux, WireGuard) | A port you reserve under Client Area › Forwarded ports, typed into **Forwarded port** |
| Mullvad | A WireGuard file from your account's WireGuard configuration page | None: Mullvad stopped offering it |
| IVPN | A WireGuard file from the Client Area's WireGuard configuration generator | None: IVPN stopped offering it |
| Windscribe | A WireGuard file from My Account › Config Generator › WireGuard (paid accounts) | An ephemeral port with Matching Port from My Account › Port Forwarding, typed into **Forwarded port**. It lasts 7 days, so request a new one and update the field when it runs out. |
| Surfshark | A WireGuard file from VPN › Manual setup › WireGuard | None |
| NordVPN | Your access token, and a **Country** if you want one. highsea fetches your key and a recommended server with it, so there's no file; see [NordVPN](#nordvpn) | None: only its Dedicated Server add-on forwards ports |
| Another WireGuard provider | Any WireGuard configuration file | A port typed into **Forwarded port**, if your provider gives you one |

The list of providers comes from highsea's catalog, so new providers can appear without a new version of highsea.

Private Internet Access asks for an account rather than a file:

![The built-in VPN with Private Internet Access chosen: two steps, then Username, Password and a Region list set to Netherlands](/images/admin/settings-vpn/connects-pia.png)

For which providers forward a port and how highsea uses it, see [Port forwarding](/settings/vpn/port-forwarding/).

## What the configuration file needs

highsea reads the file as WireGuard's own tools do, and refuses one it can't use, with the reason under the field. Besides its keys and at least one `[Peer]`, the file needs:

- an IPv4 `Address` in its `[Interface]` section;
- an `Endpoint` for each `[Peer]`;
- a `DNS` line in its `[Interface]` section. Without it, tracker names would be looked up outside the tunnel, so highsea stops torrents and the **Names** check says so.

Files downloaded from the providers above have all three.

The built-in VPN carries IPv4 only for now, so torrents use IPv4 while it's on.

## NordVPN

NordVPN has no WireGuard file to download. Instead you paste an access token, and highsea asks NordVPN for the WireGuard key that belongs to your account and for a recommended server each time it connects.

1. Sign in to Nord Account and open **NordVPN › Advanced settings › Get access token**. Enter the code NordVPN emails you, and generate a token. Copy it; it's shown once.
2. In Settings › VPN, choose **Built-in VPN**, then **NordVPN** under **Provider**, and paste the token into **Access token**.
3. Leave **Country** at **Any country** for NordVPN to recommend a server anywhere, or pick a country.
4. Press **Test** to see that it works before you save, then **Save**.

![The built-in VPN with NordVPN chosen: its steps, then Access token and a Country list set to Any country](/images/admin/settings-vpn/connects-nordvpn.png)

Once saved, the field says **Set. Type a new one to replace it.** The token stays on the server, sealed like your other secrets, and the page never shows it again. If NordVPN refuses it, the reason shows under the field: generate a new token and paste it.

To get your key and a server, highsea sends the token to NordVPN's API before the tunnel is up, since there's no tunnel without them. That's the only thing that leaves outside the tunnel; torrents wait until it's up. If a server stops answering, highsea reconnects and asks NordVPN for a fresh recommendation. NordVPN doesn't forward ports, so peers can't connect in: downloads work, and seeding reaches only the peers that accept connections.

### A file written by hand

You can still write the WireGuard file yourself, for example to stay on one server. highsea uses it only while no token is set.

1. Get your key with the token. In a terminal, run `curl -u token:YOUR_TOKEN https://api.nordvpn.com/v1/users/services/credentials` and copy the value of `nordlynx_private_key`.
2. Find a server. Open `https://api.nordvpn.com/v1/servers/recommendations?filters[servers_technologies][identifier]=wireguard_udp&limit=1` in a browser and note the `hostname`, and the `public_key` under `wireguard_udp`.
3. Write the file, putting in your key, the server's key and its hostname:

   ```ini
   [Interface]
   PrivateKey = YOUR_NORDLYNX_PRIVATE_KEY
   Address = 10.5.0.2/32
   DNS = 103.86.96.100, 103.86.99.100

   [Peer]
   PublicKey = THE_SERVER_PUBLIC_KEY
   AllowedIPs = 0.0.0.0/0
   Endpoint = THE_HOSTNAME:51820
   ```

4. Under **Or a WireGuard configuration you wrote**, upload it, or choose **Paste instead** and paste it.

The key belongs to your account, not to one server, so to change servers repeat step 2 and change only the `[Peer]` lines.
