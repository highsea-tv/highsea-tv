Written for highsea 0.1.0.

**Settings › Network and remote access** covers how highsea is reached: the address apps use away from home, a reverse proxy in front of it, HTTPS, and how apps find it on your own network.

Admins can read this area, but only the Owner can change it. For anyone else the fields are greyed out, with the line "Only the owner can change how the server is reached."

[Recommended setup](/recommended-setup/) has the short version. This page covers the choices and discovery; the pages below go through the rest.

## How highsea is reached

highsea always serves plain HTTP on port 3000, for your own network and the apps on it. For access from outside, choose one of these:

| Approach | Set **TLS** to | Set **External URL** to |
| --- | --- | --- |
| A reverse proxy you already run, such as Caddy, nginx or Traefik, handles HTTPS | [**My proxy handles it**](/settings/network/reverse-proxy-and-tls/#through-a-reverse-proxy) | The proxy's `https://` address |
| highsea serves HTTPS itself, and you forward its port on your router | [**Built in**](/settings/network/reverse-proxy-and-tls/#built-in-tls) | The `https://` address that reaches that port |
| No access from outside | **Off (LAN only)** | Leave it empty |

Setup asked which of these you wanted and filled in the settings to match. You can change them here at any time.

## Discovery

**Let apps on this network find** the server answers the apps on your own network when they look for servers, so nobody needs to type an address at home. It's on by default. It works two ways:

- **UDP broadcast** on port 7368. In Docker, this needs host networking or the published UDP port, which `compose.bridge.yaml` and `compose.connects.yaml` publish.
- **mDNS**. In Docker, highsea publishes through the host's own mDNS service (avahi) when the container has the host's `/run/dbus`, as `compose.yaml` and the NAS templates give it, and that works with published ports too. Without it, mDNS needs host networking.

Turn it off if you'd rather the server stayed quiet on the network; apps then need its address.

If highsea can't listen on the discovery port, **System › Health** warns, usually because something else on the machine uses it.

**On this network** lists the addresses highsea answers on, which you can type into an app that can't find the server.

## Settings at a glance

| Setting | Default | Who can change it |
| --- | --- | --- |
| **External URL** | Empty | Owner |
| **TLS** | **Off (LAN only)**, unless setup chose otherwise | Owner |
| **HTTPS port** | 8443 | Owner |
| **Trusted proxies** | Empty, unless setup chose a reverse proxy | Owner |
| **Use X-Forwarded-For and X-Forwarded-Proto** | Off, unless setup chose a reverse proxy | Owner |
| **Let apps on this network find** the server | On | Owner |

For the torrent port, see [Connections](/settings/downloads/connections/#listening-port). For running highsea behind a VPN, which changes how its ports are published, see [VPN](/settings/vpn/).
