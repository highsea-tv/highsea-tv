Written for highsea 0.2.0-beta.3 on DSM 7.2 or later with Container Manager, and checked on DSM 7.4.1.

Container Manager runs highsea from a compose file, which it calls a project. Its containers use published ports rather than the NAS's own network, which highsea supports.

## Before you start

- Install **Container Manager** from Package Center.
- In **Control Panel › Shared Folder**, make a shared folder called `data` on the volume with the most room. Inside it, in File Station, make `downloads` and `media/movies`. Keeping both in one shared folder is what lets highsea hardlink finished downloads into the library instead of copying them.
- In File Station, make a folder for highsea's own files, such as `docker/highsea`, and a `config` folder inside it. Container Manager may have made the `docker` shared folder already. Container Manager doesn't make a missing folder for a container: without `config`, the project stops with "Bind mount failed" and the folder's name.

highsea runs as the DSM user who made `downloads` and `media`, so the files it writes are yours. Make sure that user can read and write the `data` and `docker` shared folders, in **Control Panel › Shared Folder › Edit › Permissions**.

## Create the project

1. Open **Container Manager**, go to **Project**, and choose **Create**.
2. Fill in the first page:
   - **Project name**: `highsea`.
   - **Path**: the `docker/highsea` folder you made.
   - **Source**: **Create docker-compose.yml**, and paste the file below.
3. Leave the web portal through Web Station off; highsea serves its own.
4. Check the summary, choose **Done**, and let it start the project.

```yaml title="docker-compose.yml"
services:
  highsea:
    image: ghcr.io/highsea-tv/highsea:latest
    container_name: highsea
    volumes:
      - ./config:/config
      - /volume1/data:/data
      - /dev/dri:/dev/dri
      - /run/dbus:/run/dbus:ro
    ports:
      - "3000:3000"
      - "6881:6881/tcp"
      - "6881:6881/udp"
      - "7368:7368/udp"
    device_cgroup_rules:
      - "c 226:128 rw"
      - "c 226:129 rw"
      - "c 226:130 rw"
      - "c 226:131 rw"
      - "c 226:132 rw"
      - "c 226:133 rw"
      - "c 226:134 rw"
      - "c 226:135 rw"
    restart: unless-stopped
```

If your `data` shared folder is on another volume, change `/volume1/data` to match. Nothing else needs changing: highsea takes your time zone from your browser during setup.

The `/dev/dri` line and the rules under it give highsea the graphics chip on models with an Intel Celeron or Pentium, such as the DS920+ and DS1520+, for [hardware acceleration](/install/hardware-acceleration/). On a model without one, the project starts all the same.

The `/run/dbus` line lets highsea announce itself through DSM's own mDNS service, so apps on your network can find it by name.

`./config` is a folder inside the project's path, so highsea's database and backups sit next to its compose file.

## Run setup

Open `http://<your NAS's address>:3000`. highsea opens its setup; [Install with Docker › Run setup](/install/docker/#run-setup) walks through each step.

Setup finds `/data/media/movies` and `/data/downloads` inside the container, or makes them in an empty `data` folder, so it asks only for the owner account. On Review, **Address on your network** is the address you opened setup at, since the project uses a bridge network: check it's the NAS's address.

Apps on your network find highsea by its broadcast on port 7368 and by mDNS. If one doesn't, give it the NAS's address.

## Firewall

If DSM's firewall is on, allow TCP 3000, TCP and UDP 6881, and UDP 7368 from your network, in **Control Panel › Security › Firewall**.
