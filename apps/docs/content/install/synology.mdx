Written for highsea 0.2.0 on DSM 7.2 or later with Container Manager, and checked on DSM 7.4.1.

Container Manager runs highsea from a compose file, which it calls a project. Its containers use published ports rather than the NAS's own network, which highsea supports. There are two ways to set it up:

- [Install the package](#install-the-package), which makes the project for you. It needs DSM 7.2.1 or later.
- [Create the project yourself](#before-you-start), with a compose file you can change.

## Install the package

highsea has its own package source, which lists the package in Package Center and tells it when there's an update. The package runs the same image as the project below.

1. Install **Container Manager** from Package Center.
2. In Package Center, choose **Settings**, then **Package Sources**, and choose **Add**.
3. Type `highsea` as the **Name** and `https://packages.highsea.tv` as the **Location**, then choose **OK** twice.
4. Choose **Community** in Package Center's sidebar, find **highsea**, and choose **Install**.
5. DSM says the package isn't from Synology. Choose **Agree** to carry on.
6. On **Where your films go**, type the name of the shared folder your films are in, or keep `highsea` to make a new shared folder.
7. Read **Before you start**, check the summary, and choose **Done**.

![The package's first step, Where your films go, asking for a shared folder with highsea filled in](/images/synology-package-wizard.png)

Container Manager then downloads highsea's image and starts it, which can take a few minutes. When Package Center shows highsea as running, choose **Open**, or open `http://<your NAS's address>:3000`, and [run setup](#run-setup).

The package runs highsea as its own DSM user, `highsea`, and gives that user read and write access to the shared folder you chose. It finds the graphics chip and DSM's mDNS service by itself, so there's nothing else to choose. highsea's settings, database and backups live in the package's own folder on the volume.

If highsea already runs as a Container Manager project you made, stop and delete that project first: both use port 3000, and the package says so if the port is taken. The package starts with its own settings.

### Updates

When a new version is out, Package Center shows **Update** on highsea, under **Installed**, and notifies you if its notifications are on. Package Center checks its sources from time to time, so an update can take a while to show. To have it update highsea by itself, turn that on in **Settings › Auto-update**. The shared folder and highsea's settings are kept.

### Without the package source

Each stable release on [GitHub](https://github.com/highsea-tv/highsea-tv/releases) also has the package under **Assets**, named like `highsea-0.2.0-0001.spk`. Download it, choose **Manual Install** in Package Center, choose the file, and carry on from step 5. Package Center doesn't tell you about updates to a package installed this way: install the newer release's `.spk` the same way.

### Uninstall

Choose **Uninstall** in Package Center. Your films and the shared folder are kept. highsea's settings, database and backups are kept too, so installing again carries on where it left off, unless you tick **Also delete highsea's settings, database and backups**. To remove the package source as well, select it in **Settings › Package Sources** and choose **Delete**.

## Before you start

This section and the next are for creating the project yourself. The package does both for you.

- Install **Container Manager** from Package Center.
- In **Control Panel › Shared Folder**, make a shared folder called `data` on the volume with the most room. Inside it, in File Station, make `downloads` and `media/movies`. Keeping both in one shared folder is what lets highsea hardlink finished downloads into the library instead of copying them.
- In File Station, make a folder for highsea's own files, such as `docker/highsea`, and a `config` folder inside it. Container Manager may have made the `docker` shared folder already. Container Manager doesn't make a missing folder for a container: without `config`, the project stops with "Bind mount failed" and the folder's name.

highsea runs as the DSM user who made `downloads` and `media`, so the files it writes are yours. Make sure that user can read and write the `data` and `docker` shared folders, in **Control Panel › Shared Folder › Edit › Permissions**.

## Create the project

1. Open **Container Manager**, go to **Project**, and choose **Create**.
2. Fill in the first page:
   - **Project name**: `highsea`.
   - **Path**: the `docker/highsea` folder you made.
   - **Source**: **Create docker-compose.yml**, and paste the file below.
3. Leave the web portal through Web Station off; highsea serves its own.
4. Check the summary, choose **Done**, and let it start the project.

```yaml title="docker-compose.yml"
services:
  highsea:
    image: ghcr.io/highsea-tv/highsea:latest
    container_name: highsea
    volumes:
      - ./config:/config
      - /volume1/data:/data
      - /dev/dri:/dev/dri
      - /run/dbus:/run/dbus:ro
    ports:
      - "3000:3000"
      - "6881:6881/tcp"
      - "6881:6881/udp"
      - "7368:7368/udp"
    device_cgroup_rules:
      - "c 226:128 rw"
      - "c 226:129 rw"
      - "c 226:130 rw"
      - "c 226:131 rw"
      - "c 226:132 rw"
      - "c 226:133 rw"
      - "c 226:134 rw"
      - "c 226:135 rw"
    restart: unless-stopped
```

If your `data` shared folder is on another volume, change `/volume1/data` to match. Nothing else needs changing: highsea takes your time zone from your browser during setup.

The `/dev/dri` line and the rules under it give highsea the graphics chip on models with an Intel Celeron or Pentium, such as the DS920+ and DS1520+, for [hardware acceleration](/install/hardware-acceleration/). On a model without one, the project starts all the same.

The `/run/dbus` line lets highsea announce itself through DSM's own mDNS service, so apps on your network can find it by name.

`./config` is a folder inside the project's path, so highsea's database and backups sit next to its compose file.

![Container Manager's Create Project page, with the name, path and compose file filled in](/images/synology-create-project.png)

## Run setup

Open `http://<your NAS's address>:3000`. highsea opens its setup; [Install with Docker › Run setup](/install/docker/#run-setup) walks through each step.

Setup finds `/data/media/movies` and `/data/downloads` inside the container, or makes them in an empty `data` folder, so it asks only for the owner account. On Review, **Address on your network** is the address you opened setup at, since the project uses a bridge network: check it's the NAS's address.

Apps on your network find highsea by its broadcast on port 7368 and by mDNS. If one doesn't, give it the NAS's address.

## Firewall

If DSM's firewall is on, allow TCP 3000, TCP and UDP 6881, and UDP 7368 from your network, in **Control Panel › Security › Firewall**.
